1. Project Problem Statement (In Plain Words)

Every single second, an enterprise network processes millions of packets—emails, video calls, logins, database queries, and downloads. Hidden inside this sea of legitimate network traffic are malicious cyber attacks trying to breach databases, lock servers with ransomware, probe open ports, or shut down online operations.

Why Traditional Defense Systems (Firewalls & Static IDS) Fail: Traditional network intrusion detection systems (such as Snort or classic firewalls) depend on static signatures—pre-written static rules (e.g., "If a packet contains exact hexadecimal string X from IP Y, block it"). Attackers easily bypass these rules by:
  • Modifying exploit code slightly (polymorphic malware).
  • Obfuscating payloads or changing destination ports.
  • Using zero-day exploits (new vulnerabilities that have no existing signature).

The Solution: Next-Generation AI/ML Threat Detection. Rather than memorizing static malicious text strings, Artificial Intelligence and Machine Learning models analyze traffic behavior—such as connection duration, packet frequencies, packet sizes, sequence numbers, and Time-To-Live (TTL) discrepancies. AI learns how normal traffic behaves vs. anomalous attack patterns, allowing it to spot brand-new, unseen attacks in near real-time.

The Core Engineering Challenge (False Positives vs. False Negatives): In network security, you face two opposite dangers:
  1. False Negative (FN) - Missed Attack: An attacker sneaks in unnoticed $\rightarrow$ leads to ransomware or catastrophic data theft.
  2. False Positive (FP) - False Alarm: A legitimate employee or customer is misidentified as a hacker $\rightarrow$ their connection is terminated, creating an accidental Self-Inflicted Denial of Service and exhausting SOC analysts.
This project builds and benchmarks a complete end-to-end pipeline to solve this exact dual challenge.

2. The Three Dataset Files Explained: Why 3 Files?

The UNSW-NB15 benchmark was generated at the Australian Cyber Security Centre (ACCS) using an IXIA PerfectStorm simulation rig to synthesize 100 GB of modern normal traffic and 9 types of sophisticated attacks. The project utilizes three distinct files:

Filename Records File Size Role in Pipeline Target Split
UNSW_NB15_training-set.csv 175,341 ~32.1 MB Model Training & Preprocessor Fitting Normal: 56,000 (31.9%)
Attack: 119,341 (68.1%)
UNSW_NB15_testing-set.csv 82,332 ~15.3 MB Untouched Blind Evaluation Benchmark Normal: 37,000 (44.9%)
Attack: 45,332 (55.1%)
UNSW-NB15_features.csv 44 Rows ~3.2 KB Feature Dictionary & Metadata Schema Documentation & Schema Definition

Why Are There Three Separate Datasets Instead of Just One?

  • 1. Strict Academic Standardization & Benchmark Reproducibility: If researchers randomly split a single dataset using train_test_split(test_size=0.2), every university and researcher would test on different random subsets, making fair comparison impossible. The creators of UNSW-NB15 officially defined these two specific train/test files so any research paper or engineer in the world can be benchmarked on identical test conditions.
  • 2. Preventing "Data Snooping" and Contamination: In cybersecurity, models in production face incoming traffic from tomorrow, not yesterday. Keeping a completely untouched testing set ensures our models do not overfit to specific source IPs, session IDs, or synthetic time artifacts present in the training set.
  • 3. The Metadata / Schema Dictionary (UNSW-NB15_features.csv): Raw PCAP packet captures contain thousands of low-level variables. This 3rd file serves as the official data dictionary, explaining the data type (float, integer, categorical), group (Basic, Content, Time, Generated), and technical definition of all 42 network features.

3. Network Features Explained in Simple Terms

The dataset contains 42 input features (after removing row index id and the attack label). To understand what the AI actually sees, we categorize them into 4 plain-language groups:

Feature Group Key Feature Names What It Measures (Plain English) Cybersecurity Significance
1. Basic Traffic Features dur, proto, service, state, spkts, dpkts, sbytes, dbytes, rate, sttl, dttl Connection duration, protocol used (TCP, UDP, ICMP), service (HTTP, DNS, FTP), number of packets, raw bytes transferred, and packet rate. Dead Giveaway: sttl (Source Time-To-Live). Normal Windows/Linux machines use standard TTLs (64 or 128). Automated scanning tools or spoofed IP packets often present erratic TTL values like 254.
2. Content & Payload Features sload, dload, sloss, dloss, swin, dwin, smean, dmean, trans_depth, response_body_len Bits per second transfer speed, packet loss/retransmissions, TCP window advertisement sizes, and average packet byte size. Identifies data exfiltration (huge outbound sbytes) or Denial of Service flooding (huge sload with high packet drop sloss).
3. Time & Jitter Features sinpkt, dinpkt, sjit, djit, tcprtt, synack, ackdat Microsecond inter-arrival time between packets, network jitter, and TCP 3-way handshake round trip times. Normal human browsing is bursty and irregular. Automated attack tools (like botnet scripts or Port Scanners) blast packets at rigidly uniform microsecond intervals.
4. Connection Flow (Generated) Features ct_srv_src, ct_state_ttl, ct_dst_ltm, ct_src_dport_ltm, ct_srv_dst, is_sm_ips_ports Historical window counters: tracks how many connections have been made to the same destination port, same IP, or same service in the last 100 connections. DoS & Reconnaissance Detector: If a single IP makes 90 connections to 90 different ports in 100 milliseconds (ct_dst_sport_ltm is high), it is an active Port Scan (Nmap).

4. The Threat Landscape: 9 Attack Categories (MITRE ATT&CK Mapped)

Malicious traffic in the dataset is labeled under attack_cat across 9 distinct threat categories:

  • Generic (33.6%): Cryptographic collision attacks and generic cipher bypasses that evade standard signature engines.
  • Exploits (25.4%): Direct weaponized attacks targeting known software bugs (buffer overflows, SQL injections) to gain unauthorized access.
  • Fuzzers (13.8%): Automated tools that blast servers with random, oversized, or illegal packet structures to induce system crashes.
  • DoS - Denial of Service (9.3%): Connection flooding attacks designed to exhaust server CPU, memory, or bandwidth.
  • Reconnaissance (8.0%): Port scanning and network topology discovery (e.g., Nmap scans looking for open doors).
  • Analysis (1.5%): Vulnerability scanners that crawl web apps looking for HTML/parameter injection weaknesses.
  • Backdoor (1.3%): Stealthy remote access tools installed on compromised machines allowing covert operator control.
  • Shellcode (0.9%): Tiny snippets of machine code injected into memory buffers to spawn an interactive shell.
  • Worms (0.1%): Self-replicating autonomous malware that spreads across the network without human interaction (rarest category).

5. Data Preprocessing: What Was Done vs. What Was NOT Done (And Why)

Data preprocessing determines whether a machine learning model learns true cybersecurity physics or merely memorizes synthetic dataset noise. Here is the strict breakdown:

Action Pipeline Operation Status Why This Decision Was Made (Technical Justification)
1. Remove id df.drop(columns=['id']) DONE Prevents Shortcut Learning: The id column is simply a row counter (1, 2, 3...). In the raw data, attacks were captured in specific time batches, so row index correlates artificially with attack labels. Leaving id in would teach the model to predict attacks based on line numbers!
2. Isolate attack_cat Remove from feature matrix $X$; store in separate array DONE Prevents Target Leakage: attack_cat explicitly spells out the attack name ("DoS", "Exploits"). In a binary classification task ($0$ vs $1$), leaving the attack category in the inputs would be massive label leakage. It was preserved strictly for Task 5 ethical bias evaluation.
3. Handle Missing Values fillna(X_train[num_cols].median()) DONE Network features like packet rates and durations have extreme positive skew. Using median rather than mean prevents extreme outlier flows from biasing missing value replacements.
4. Categorical Encoding LabelEncoder on proto, service, state DONE Converts string protocols ('tcp', 'udp', 'icmp') into numeric integers so matrix multiplication and decision splits can process them mathematically.
5. Standard Feature Scaling StandardScaler fit on Train ONLY; transform on Test DONE Critical ML Hygiene: Neural Networks (MLP) and Logistic Regression will fail or diverge if feature values range from $0.0001$ to $10,000,000$. Normalizing to mean $\mu=0$ and variance $\sigma=1$ ensures balanced gradient updates. Scaling parameters were computed solely on the training data to prevent test leakage.
6. Synthetic Oversampling (SMOTE) Generating artificial packets NOT DONE Why Omitted: Generating fake synthetic packets (like SMOTE) distorts real-world network physics. In production networks, normal traffic is abundant and specific attacks (like Worms) are rare. Training on fake packets creates high False Positive Rates on real enterprise traffic.
7. Retrospective Resplitting Combining & randomly shuffling train/test NOT DONE Why Omitted: The dataset creators intentionally split train and test to represent distinct capture time intervals. Merging and re-splitting would artificially inflate test scores and violate the benchmark specification.

7. Empirical Results: All Model Accuracies & Full Metric Benchmark

All four models were trained on the 175,341 training flows and evaluated on the 82,332 completely untouched test records.

Model Architecture Accuracy Precision Recall (Detection Rate) F1-Score ROC-AUC False Positive Rate (FPR) Training Time Inference Latency (10k packets)

Decision Tree (Rule-Based Engine) 85.36% 80.72% 96.46% 0.8789 0.9625 28.23% 2.81s 2.47 ms

Which Model Was Used and WHY Was It Chosen?

  • 1. Logistic Regression: Serves as our mathematical linear baseline. It asks: "Can network threats be cleanly separated with a simple hyper-plane?" Result: While it is ultra-fast (1.7 ms inference), its linear nature leads to an unacceptable 39.78% False Positive Rate.
  • 2. Decision Tree Classifier: Network intrusion signatures are inherently rule-driven (e.g., "IF protocol == TCP AND port == 80 AND packet_size > 1500 THEN flag"). Decision trees mirror this exact logic. Constrained to max_depth=12, it delivers 85.36% accuracy with blazing-fast 2.47 ms inference, making it 100% human-interpretable for SOC security analysts.
  • 3. Random Forest (100 Trees): Solves the decision tree's tendency to overfit by training an ensemble of 100 decorrelated trees. It emerged as the Overall Champion with a staggering 98.92% Recall and an outstanding 0.9831 ROC-AUC, missing only 1.08% of cyber threats across the entire test set.
  • 4. Multi-Layer Perceptron (Deep Learning): A 3-layer neural network (Input $\rightarrow$ 128 ReLU $\rightarrow$ 64 ReLU $\rightarrow$ Sigmoid output). Deep Learning was deployed to test whether multi-layer hierarchical abstractions could outperform decision trees on raw network flow statistics.

8. Why Compare ML vs. DL? What Is the Benefit?

In modern cybersecurity marketing, "Deep Learning" and "Neural Networks" are often hyped as universally superior. A primary research objective of this project is to perform an honest, empirical comparison between Classical Machine Learning and Deep Learning.

The Key Findings & Benefits of the ML vs. DL Comparison:
  1. Tabular Data Reality: On structured, tabular network flow features, Tree Ensembles (Random Forest) outperform Deep Neural Networks (MLP: 85.71% vs RF: 86.47% accuracy; Recall: 96.94% vs RF: 98.92%).
  2. Training Efficiency: Decision Tree trained in 2.81 seconds and Random Forest in 18.49 seconds, whereas the Deep Learning MLP required 180.06 seconds (~3 minutes)—a 10x to 60x computational penalty with no gain in detection rate!
  3. Edge Firewall Deployment: Network routers (Cisco, Fortinet) operate on limited CPU hardware. Decision Trees require only 2.47 ms per 10,000 packets and simple IF/ELSE memory structures that can be compiled directly onto FPGA silicon or eBPF kernel hooks. Deep Learning networks require floating-point matrix multiplications that choke low-power edge gateways.
  4. Explainability (XAI) in the SOC: When a firewall drops a CEO's packet or isolates a server, the Security Operations Center (SOC) analyst must answer: "Why was this blocked?" Decision trees provide clear inspection pathways, while Deep Neural Networks act as black boxes.

9. Ethical Considerations & SOC Operational Threshold Tuning

Standard classification defaults to a 50% probability threshold ($\tau = 0.50$). However, evaluating this default in a real-world Security Operations Center reveals a serious operational crisis:

The Default Threshold Crisis ($\tau = 0.50$): At $\tau = 0.50$, the False Positive Rate is 28.78%. That means out of 37,000 legitimate normal sessions in the test set, 10,648 real users are blocked! In a university or hospital, shutting off 28% of legitimate users causes widespread disruption, angry tickets, and analyst burnout.

The Solution: Operational Threshold Tuning ($\tau = 0.82$)

In src/ethical_sim.py, we sweep the decision threshold across 37 points. Shifting the threshold from $\tau = 0.50 \rightarrow 0.82$:

  • False Positive Rate drops from 28.78% down to 5.57% (a 5x reduction in false alarms!).
  • Precision jumps from 80.81% to 95.22% (when an alarm rings, analysts are 95% confident it is real).
  • Security Coverage remains solid at 90.67% Recall.
